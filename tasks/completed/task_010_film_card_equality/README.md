# Задача №10 — Когда карточки фильма считаются одинаковыми?

**Сложность:** начальная, новый шаг в работе с объектами.

**Тема:** карточки фильмов.

## Что закрепляем и изучаем

- Закрепляем: объекты, конструктор, приватное состояние, строки и переопределение методов `Object`.
- Новые понятия: логическое равенство объектов через `equals()` и согласованный с ним `hashCode()`.

Оператор `==` отвечает, ссылаются ли две переменные на один и тот же объект. Метод `equals()` может отвечать на другой вопрос: содержат ли два разных объекта одинаковые значимые данные. Если два объекта равны через `equals()`, их `hashCode()` обязан возвращать одинаковое число. Обратное неверно: одинаковый хеш ещё не доказывает равенство.

## Условие

Создай публичный класс `FilmCard` в пакете `learning.task010`. Карточка хранит название фильма и год выхода. Две карточки считаются равными, только если совпадают **и название целиком (с учётом регистра), и год**.

Внешний контракт:

```java
public FilmCard(String title, int releaseYear)
public boolean equals(Object other)
public int hashCode()
```

- Переопредели оба метода `Object`: `equals` сравнивает значимые данные карточек, `hashCode` использует те же данные.
- `equals(null)` возвращает `false`; объект другого класса также не равен карточке.
- Название гарантированно непустое. Год находится в диапазоне `1888..2100` включительно. Проверять аргументы конструктора не требуется.
- Все данные объекта храни в приватном состоянии. Не используй ввод или вывод в консоль.
- Не сравнивай названия через `==`: строки с одинаковыми буквами могут быть разными объектами.
- Не требуй, чтобы неравные карточки обязательно имели разные хеши: совпадение хешей допустимо.

### Примеры

| Первая карточка | Вторая карточка | Результат `equals` |
|---|---|:---:|
| `("Дюна: Часть вторая", 2024)` | `("Дюна: Часть вторая", 2024)` | `true` |
| `("Дюна", 2024)` | `("Дюна", 1984)` | `false` |
| `("Дюна", 2024)` | `("Бегущий по лезвию", 2024)` | `false` |

Для двух разных карточек из первой строки значения `hashCode()` тоже должны совпасть.

## Учебный пример: координата места

Пример сравнивает координаты по ряду и месту. Это другой предмет, но использует тот же приём: если оба значения совпали, объекты равны; хеш строится из этих же значений.

```java
class SeatCoordinate {
    private int row;
    private int seat;

    SeatCoordinate(int row, int seat) {
        this.row = row;
        this.seat = seat;
    }

    @Override
    public boolean equals(Object other) {
        if (this == other) {
            return true;
        }
        if (!(other instanceof SeatCoordinate)) {
            return false;
        }
        SeatCoordinate coordinate = (SeatCoordinate) other;
        return row == coordinate.row && seat == coordinate.seat;
    }

    @Override
    public int hashCode() {
        return 31 * row + seat;
    }

    public static void main(String[] args) {
        Object first = new SeatCoordinate(4, 12);
        Object second = new SeatCoordinate(4, 12);
        System.out.println(first.equals(second));
        System.out.println(first.hashCode() == second.hashCode());
    }
}
```

- В конструкторе каждый объект сохраняет свой ряд и место.
- `this == other` быстро распознаёт ссылку на тот же самый объект.
- `instanceof` проверяет тип второго объекта. После проверки приведение `(SeatCoordinate) other` позволяет обратиться к его полям.
- `row == coordinate.row && seat == coordinate.seat` сравнивает обе координаты. Для строк в задаче вместо `==` используй сравнение содержимого строки.
- `hashCode()` использует ряд и место — те же значения, что сравнивает `equals()`. Число `31` помогает смешать два значения; формула не обязана давать уникальное число для каждой координаты.
- В `main` переменные имеют тип `Object`, но методы вызываются у реальных `SeatCoordinate`. На экране появятся `true` и `true`.

Путь данных: конструктор получает значения → сохраняет их в каждом объекте → `equals()` сравнивает значимые поля → `hashCode()` вычисляет число из тех же полей → вызвавший код получает результат. Автотесты проверят одинаковые и отличающиеся карточки, правила `equals`, согласованность хешей, границы годов, приватность состояния и публичный внешний контракт.

## Ограничения и готовность

- Создай реализацию самостоятельно; готового класса в `src/main` нет.
- Равенство должно учитывать одновременно название и год; регистр букв важен.
- Соблюдай правило: если `a.equals(b)` равно `true`, то `a.hashCode()` должен совпадать с `b.hashCode()`.
- Не делай выводов о равенстве объектов только по хешу.
- Задача готова, когда проходят все тесты и соблюдены ограничения условия.
