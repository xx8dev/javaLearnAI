# Задача №15 — Что именно купили в цифровом магазине?

**Сложность:** начальная, новый шаг после классов, наследования и абстрактных классов.

**Тема:** один класс для записей о покупках разных типов товаров.

## Что закрепляем и изучаем

- Закрепляем: классы, конструкторы, поля, инкапсуляцию, методы с возвращаемым значением и проверку входных данных.
- Новое понятие: параметр типа и обобщённый класс (`generic class`). Параметр типа позволяет классу хранить объект выбранного типа, а компилятору — проверять этот тип при присваивании и чтении.

В записи о покупке могут храниться фильм, игровое дополнение или другой объект. Без обобщений понадобился бы отдельный класс для каждого вида товара либо пришлось бы возвращать слишком общий тип `Object`. Обобщённый класс описывает общую запись один раз и сохраняет точный тип товара.

## Учебный пример: бирка на коробке

```java
class ShelfLabel<T> {
    private final T value;

    ShelfLabel(T value) {
        this.value = value;
    }

    T getValue() {
        return value;
    }
}

public class ShelfLabelDemo {
    public static void main(String[] args) {
        ShelfLabel<String> label = new ShelfLabel<>("Саундтрек к фильму");
        String text = label.getValue();
        System.out.println(text);
    }
}
```

- `ShelfLabel<T>` объявляет параметр типа `T`: при создании объекта вместо `T` будет выбран конкретный ссылочный тип.
- `private final T value` хранит выбранный объект; `private` закрывает поле, а `final` не позволяет заменить его после конструктора.
- `ShelfLabel<String>` означает, что в этой записи хранится `String`. Алмазный оператор `<>` позволяет Java вывести тот же тип справа.
- `getValue()` возвращает `String`, поэтому результат можно сразу присвоить переменной `String` без приведения типа.
- При запуске текст `Саундтрек к фильму` проходит через конструктор, сохраняется в поле, возвращается методом и выводится в консоль.

Параметрами типа могут быть ссылочные типы, например `String` или `Integer`; примитивный `int` указывается как `Integer`.

## Условие

Создай публичный обобщённый класс `DigitalPurchase<T>` в пакете `learning.task015`. Он описывает покупку цифрового товара и хранит сам товар вместе с потраченной суммой в рублях. Один и тот же класс должен подходить для разных типов товаров.

Внешний контракт:

```java
public DigitalPurchase(T item, int priceRubles)
public T getItem()
public int getPriceRubles()
```

Правила:

- Товар не может быть `null`; в этом случае конструктор выбрасывает `IllegalArgumentException`.
- Цена находится в диапазоне `0..1_000_000` включительно. За пределами диапазона конструктор выбрасывает `IllegalArgumentException`.
- После создания записи товар и цена не меняются. Поля должны быть закрыты от прямого доступа.
- Класс не печатает результат и не хранит другие данные о покупке.

### Примеры

| Тип товара | Цена | Что возвращают методы |
|---|---:|---|
| `String` с названием фильма | `350` | исходную строку и `350` |
| объект игрового дополнения | `1_000_000` | тот же объект и `1_000_000` |
| `String` с названием бесплатного бонуса | `0` | исходную строку и `0` |

Если создать `DigitalPurchase<String>`, метод `getItem()` должен иметь для вызывающего кода тип `String`. Для другого ссылочного типа можно создать `DigitalPurchase<SomeItem>`; класс при этом остаётся тем же.

## Критерии готовности

- `DigitalPurchase<T>` — публичный класс с одним параметром типа.
- Один объект класса сохраняет товар любого ссылочного типа вместе с ценой; методы возвращают сохранённые значения.
- Нулевой и максимальный допустимый ценник принимаются, `null`, отрицательная цена и цена выше предела отклоняются.
- Состояние закрыто от прямого изменения после создания; методы не печатают в консоль.
- Все автоматические тесты проходят.
