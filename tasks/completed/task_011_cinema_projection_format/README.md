# Задача №11 — Как учесть формат кинопоказа?

**Сложность:** начальная.

**Тема:** стоимость билета для разных форматов кинопоказа.

## Что закрепляем и изучаем

- Закрепляем: классы, объекты, конструкторы, приватное состояние и условные проверки.
- Новое понятие: `enum` — тип с заранее заданным конечным набором значений.

Для формата показа подходят только известные варианты. Если хранить их строками, можно случайно передать `"Imax"`, `"imax"` или опечататься. Значение перечисления выбирается из объявленных вариантов, поэтому Java проверяет его при компиляции.

## Условие

Создай публичное перечисление `ProjectionFormat` в пакете `learning.task011` с ровно тремя значениями:

```java
STANDARD, THREE_D, IMAX
```

Создай в том же пакете публичный класс `CinemaScreeningPrice`. Он получает формат и базовую цену билета и возвращает итоговую цену.

Внешний контракт:

```java
public CinemaScreeningPrice(ProjectionFormat format, int basePriceRubles)
public int getTotalPriceRubles()
```

Надбавки к базовой цене:

| Формат | Надбавка |
|---|---:|
| `STANDARD` | `0` рублей |
| `THREE_D` | `120` рублей |
| `IMAX` | `250` рублей |

Базовая цена гарантированно находится в диапазоне `0..10_000` рублей включительно, формат всегда является одним из значений перечисления. Проверять аргументы конструктора не нужно. Итоговая цена — базовая цена плюс надбавка выбранного формата. Повторные вызовы метода возвращают тот же результат. Не читай ввод и не печатай из класса.

### Примеры

| Формат | Базовая цена | Итог |
|---|---:|---:|
| `STANDARD` | `700` | `700` |
| `THREE_D` | `700` | `820` |
| `IMAX` | `700` | `950` |

## Учебный пример: способ доставки

В примере перечисление ограничивает варианты доставки двумя значениями. Объект получает одно из них и добавляет надбавку для экспресс-доставки.

```java
enum DeliverySpeed {
    REGULAR,
    EXPRESS
}

class DeliveryQuote {
    private DeliverySpeed speed;
    private int baseFeeRubles;

    DeliveryQuote(DeliverySpeed speed, int baseFeeRubles) {
        this.speed = speed;
        this.baseFeeRubles = baseFeeRubles;
    }

    int getTotalFeeRubles() {
        if (speed == DeliverySpeed.EXPRESS) {
            return baseFeeRubles + 250;
        }
        return baseFeeRubles;
    }
}

public class Demo {
    public static void main(String[] args) {
        DeliverySpeed selectedSpeed = DeliverySpeed.EXPRESS;
        DeliveryQuote quote = new DeliveryQuote(selectedSpeed, 400);
        System.out.println(quote.getTotalFeeRubles());
    }
}
```

- `DeliverySpeed` объявляет только `REGULAR` и `EXPRESS`; строки с опечатками передать вместо такого значения нельзя.
- Поле `speed` хранит выбранное значение перечисления, а конструктор получает его вместе с базовой стоимостью.
- Условие сравнивает значение перечисления с `DeliverySpeed.EXPRESS`. Для констант `enum` можно применять `==`.
- Метод возвращает базовую цену с надбавкой или без неё; он не печатает результат.
- В `main` сначала выбирается вариант доставки → он передаётся в конструктор → метод считает стоимость → `println` показывает `650`.

Путь данных в задаче такой же: вызывающий код выбирает `ProjectionFormat` → передаёт его с базовой ценой в конструктор → объект сохраняет данные → метод возвращает итоговую цену. Тесты проверят все форматы, граничные базовые цены, повторный вызов, независимость объектов и публичный контракт.

## Ограничения и готовность

- Создай перечисление и класс самостоятельно; заготовок в `src/main` нет.
- В перечислении должны быть только три значения из условия.
- При расчёте используй надбавку, соответствующую выбранному значению.
- Поля объекта должны быть приватными; объекты с разными входными данными не должны влиять друг на друга.
- Задача готова, когда проходят все автоматические тесты и соблюдены требования.


Пока перечисление и класс не созданы, тесты ожидаемо не скомпилируются. После этого они проверят расчёт каждой надбавки и границы базовой цены.
