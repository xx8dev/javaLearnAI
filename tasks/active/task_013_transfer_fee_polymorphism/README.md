# Задача №13 — Как разные способы перевода рассчитывают комиссию?

**Сложность:** начальная, новый шаг в объектно-ориентированном программировании.

**Тема:** комиссия за перевод денег.

## Что закрепляем и изучаем

- Закрепляем: классы, методы и целочисленную арифметику.
- Новые понятия: наследование и полиморфизм через переопределение метода.

Наследование позволяет новому классу получить поведение базового класса и добавить или переопределить метод. В Java связь объявляется словом `extends`.

Полиморфизм позволяет хранить разные объекты-наследники в переменной типа общего родителя и вызывать у них один метод. Если наследник переопределил этот метод, Java выбирает реализацию по фактическому объекту.

## Учебный пример: правила доставки

```java
class DeliveryChargeRule {
    int calculate(int packageCount) {
        return 0;
    }
}

class PerPackageChargeRule extends DeliveryChargeRule {
    @Override
    int calculate(int packageCount) {
        return packageCount * 20;
    }
}

class FlatDeliveryChargeRule extends DeliveryChargeRule {
    @Override
    int calculate(int packageCount) {
        return 80;
    }
}

public class Demo {
    public static void main(String[] args) {
        int packageCount = 3;
        DeliveryChargeRule rule = new PerPackageChargeRule();
        int charge = rule.calculate(packageCount);
        System.out.println(charge);
    }
}
```

- `DeliveryChargeRule` — базовый класс; его правило по умолчанию возвращает нулевую комиссию.
- Классы с `extends DeliveryChargeRule` наследуют это поведение и переопределяют `calculate` по своим правилам.
- `@Override` указывает, что метод наследника заменяет метод базового класса; компилятор проверяет совпадение сигнатуры.
- `PerPackageChargeRule` умножает `3` посылки на `20`, а `FlatDeliveryChargeRule` возвращает фиксированные `80`.
- Переменная `rule` имеет общий тип, но хранит объект `PerPackageChargeRule`. При вызове `rule.calculate(3)` выполняется метод этого фактического объекта, поэтому результат равен `60`.
- Если заменить создаваемый объект на `FlatDeliveryChargeRule`, тот же вызов вернёт `80`. `println` показывает полученный результат.

Так проходит значение: количество посылок → объект выбранного правила → переопределённый расчёт → число комиссии → вывод результата.

## Условие

Создай три отдельных публичных класса в пакете `learning.task013` для двух правил банковского перевода.

Создай публичный базовый класс `TransferFeeRule` с публичным методом `calculateFeeRubles(int transferAmountRubles)`. Базовая реализация возвращает `0` рублей; наследники переопределяют её.

Создай два публичных класса-наследника:

- `FixedTransferFee` возвращает фиксированную комиссию `30` рублей.
- `PercentTransferFee` возвращает `5%` от суммы перевода; дробная часть рубля отбрасывается.

Сумма перевода всегда находится в диапазоне `100..100_000` рублей включительно. Проверять её не нужно. Ни один метод не должен печатать результат.

### Примеры

| Правило | Перевод | Комиссия |
|---|---:|---:|
| фиксированное | `100` | `30` |
| фиксированное | `10_000` | `30` |
| процентное | `100` | `5` |
| процентное | `999` | `49` |
| процентное | `1_000` | `50` |
| процентное | `100_000` | `5_000` |

## Внешний контракт и файлы

Каждый класс размести в отдельном файле:

```text
src/main/java/learning/task013/TransferFeeRule.java
src/main/java/learning/task013/FixedTransferFee.java
src/main/java/learning/task013/PercentTransferFee.java
```

Оба правила должны реализовать `calculateFeeRubles` с соответствующей формулой. Их также можно вызывать через переменную типа `TransferFeeRule`; тесты проверят, что при таком вызове выбирается правило фактического объекта.

## Критерии готовности

- `TransferFeeRule` — публичный класс с публичным методом по умолчанию, возвращающим `0`.
- `FixedTransferFee` и `PercentTransferFee` — публичные наследники, каждый переопределяет метод.
- Комиссия соответствует обычным примерам и граничным суммам.
- Вызов через ссылку типа `TransferFeeRule` возвращает результат выбранного наследника.
- Расчёт не хранит состояние и ничего не печатает.
- Все автоматические тесты проходят.

Тесты тренера находятся по пути `src/test/java/learning/task013/Task013TransferFeePolymorphismTest.java`. Запусти их из корня проекта:

```shell
.\mvnw.cmd test
```

Пока классы решения не созданы, тесты ожидаемо не скомпилируются. Структуру и реализацию создай самостоятельно.
