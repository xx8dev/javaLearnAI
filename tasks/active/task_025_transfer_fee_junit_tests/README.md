# Задача №25 — Как проверить комиссию отдельными тестами?

**Сложность:** начальная, первые собственные unit-тесты на JUnit 5.

**Закрепляем:** статические методы, условия, целочисленное деление, границы входных данных и исключения.

**Новое понятие:** unit-тест — небольшой автоматический тест одной части программы. В JUnit 5 аннотация `@Test` помечает тестовый метод, а утверждения вроде `assertEquals` сравнивают ожидаемый результат с фактическим.

## Зачем это нужно

Комиссия влияет на итог перевода, поэтому важно заранее проверить обычные расчёты, границы и неверные входные данные. Unit-тест запускает метод с конкретными значениями и сообщает, если поведение не совпало с ожидаемым.

## Учебный пример: тест длины кода

```java
import org.junit.jupiter.api.Test;

import static org.junit.jupiter.api.Assertions.assertEquals;

class CodeLengthTest {
    @Test
    void countsCharactersInCode() {
        String code = "A17";                  // подготовили входные данные
        int actual = code.length();            // вызвали проверяемый метод
        assertEquals(3, actual);               // проверили ожидаемый результат
    }
}
```

- `@Test` сообщает JUnit, что этот метод нужно выполнить как тест.
- `code` — подготовленные данные, а `code.length()` — действие, результат которого проверяем.
- `assertEquals(3, actual)` сравнивает ожидаемое значение `3` с тем, что вернул код. Если значения различаются, тест становится красным.
- Maven запускает тестовый класс автоматически во время `test`; метод `main` для этого не нужен.

## Условие

Создай публичный класс `TransferFeeCalculator` в пакете `learning.task025` с публичным статическим методом:

```java
int calculateFeeRubles(int transferAmountRubles, int feePercent)
```

Комиссия — указанный процент от суммы перевода. Дробная часть отбрасывается целочисленным делением. Допустимая сумма: от `0` до `1_000_000` рублей включительно; допустимый процент: от `0` до `100` включительно. Если любой аргумент выходит за диапазон, выброси `IllegalArgumentException`.

Кроме класса с расчётом самостоятельно напиши JUnit 5 тестовый класс `TransferFeeCalculatorTest` в файле `src/test/java/learning/task025/TransferFeeCalculatorTest.java`.

В собственных тестах проверь не меньше пяти разных случаев:

- обычный расчёт комиссии;
- отбрасывание дробной части;
- граничные значения суммы или процента;
- недопустимую сумму;
- недопустимый процент.

Для числовых результатов используй `assertEquals`, а для ожидаемого исключения — `assertThrows`. Каждый тест должен вызывать метод расчёта и проверять результат или ожидаемое исключение.

## Примеры

- сумма `12_500`, ставка `3` → комиссия `375`;
- сумма `99`, ставка `10` → комиссия `9`;
- сумма `500`, ставка `100` → комиссия `500`.

## Критерии готовности

- Решение и собственные JUnit-тесты находятся в указанных пакетах и каталогах.
- Тестовый класс содержит минимум пять методов с `@Test`.
- Тесты покрывают обычный случай, целочисленное округление вниз, границу и ошибочные значения.
- Все собственные и тренерские тесты проходят командой Maven.

## Где создавать файлы

- Класс с расчётом: `src/main/java/learning/task025/TransferFeeCalculator.java`.
- Твои тесты: `src/test/java/learning/task025/TransferFeeCalculatorTest.java`.
- Автоматические проверки тренера: `src/test/java/learning/task025/Task025TransferFeeJUnitTest.java`.
- Учебный пример оставь в этом README, не копируй его в исходники.

Пока класс и тестовый класс не созданы, сборка может завершаться ошибкой компиляции — это ожидаемо. После реализации запусти из корня проекта:

```powershell
.\mvnw.cmd test
```
