# Задача №8 — Как защищать баланс игрового кошелька?

**Сложность:** начальная.

**Тема:** виртуальный кошелёк игрового аккаунта.

## Что закрепляем и изучаем

- Закрепляем: класс и объект, конструктор, поля, нестатические методы, `int`, `boolean` и проверки `if`.
- Новое понятие: инкапсуляция изменяемого состояния объекта.

Баланс меняется во время работы программы. Если любое место кода сможет записать в поле произвольное значение, например отрицательный баланс, правила кошелька легко нарушить. Инкапсуляция прячет состояние внутри объекта и разрешает менять его только через методы, которые проверяют правила.

## Условие

Создай класс `GameWallet` в пакете `learning.task008`. Кошелёк хранит баланс в рублях. Создай следующий внешний контракт:

```java
public GameWallet(int initialBalanceRubles)
public int getBalanceRubles()
public boolean deposit(int amountRubles)
public boolean spend(int amountRubles)
```

Начальный баланс всегда находится в диапазоне от `0` до `1 000 000` рублей включительно.

- `getBalanceRubles()` возвращает текущий баланс.
- `deposit(amountRubles)` добавляет деньги, если сумма положительная и после пополнения баланс не превысит `1 000 000`. При успешном пополнении верни `true` и сохрани новый баланс. Иначе верни `false`, оставив баланс прежним.
- `spend(amountRubles)` списывает деньги, если сумма положительная и не превышает текущий баланс. При успешном списании верни `true` и сохрани новый баланс. Иначе верни `false`, оставив баланс прежним.

Поле баланса должно быть `private`: снаружи нельзя напрямую менять его значение. Меняй баланс только внутри `deposit` и `spend`. Методы объекта не объявляй `static`. Класс не читает ввод и не печатает результат.

### Примеры

| Начальный баланс | Операция | Результат операции | Баланс после операции |
|---:|---|:---:|---:|
| `5 000` | пополнить на `1 000` | `true` | `6 000` |
| `5 000` | списать `1 200` | `true` | `3 800` |
| `5 000` | списать `6 000` | `false` | `5 000` |
| `1 000 000` | пополнить на `1` | `false` | `1 000 000` |

## Учебный пример: энергия персонажа

Персонаж начинает с двумя единицами энергии. Метод `useOneUnit()` меняет её только при наличии энергии; вызывающий код не записывает значение в поле напрямую.

```java
public class PlayerEnergy {
    private int energy;

    public PlayerEnergy(int startingEnergy) {
        energy = startingEnergy;
    }

    public boolean useOneUnit() {
        if (energy == 0) {
            return false;
        }
        energy = energy - 1;
        return true;
    }

    public int currentEnergy() {
        return energy;
    }

    public static void main(String[] args) {
        PlayerEnergy playerEnergy = new PlayerEnergy(2);
        boolean used = playerEnergy.useOneUnit();
        System.out.println(used + ", " + playerEnergy.currentEnergy());
    }
}
```

- `private int energy;` хранит состояние внутри объекта; другой код не может присвоить этому полю значение напрямую.
- `new PlayerEnergy(2)` создаёт объект, а конструктор записывает в него начальные `2` единицы.
- `useOneUnit()` сначала проверяет, есть ли энергия. Если её нет, метод возвращает `false` и ничего не меняет.
- При наличии энергии метод уменьшает поле на один и возвращает `true`.
- `currentEnergy()` сообщает текущее состояние, не открывая поле для прямой записи.
- В `main` метод успешно расходует одну единицу; вывод будет `true, 1`.

Путь данных: конструктор получает `2` → сохраняет значение в поле объекта → `useOneUnit()` проверяет и уменьшает его до `1` → `currentEnergy()` возвращает `1` → программа печатает `true, 1`.

## Ограничения и готовность

- Начальный баланс гарантированно находится в допустимом диапазоне; проверять аргумент конструктора не требуется.
- Успешные операции изменяют баланс ровно один раз.
- Неуспешные операции не изменяют баланс.
- Поле баланса закрыто от прямого доступа; его меняют только методы объекта.
- Тесты проверяют границы баланса, неверные суммы, сохранение прежнего значения при отказе и независимость кошельков.
- Задача готова, когда все тесты проходят и правило инкапсуляции соблюдено.
